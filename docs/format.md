# 출력 형식 명세 (3층)

원형: DAIS 위키 `conference/kdd2026-transcripts`, `conference/kdd2026-summaries`, 동료가 재구성한 2026 AI TECH DAY 종합 리포트.
모든 파일은 한국어 평서체 단문("~다"). 추측은 "추정"으로, 발표자 해석은 "발표자의 해석이다"로 표시한다.
수치는 발언값과 원문값이 다르면 둘 다 적고, 외부 인용은 원문값으로 한다. 전사는 고치지 않고 노트에 상충으로 적는다.
이 문서의 형식이 기본이다. 사용자 형식(템플릿·프롬프트·필수 절)이 있으면 그것을 쓴다([README 형식 바꾸기](../README.md#형식-바꾸기)).

## 공통 식별자

- 발표 번호 `NN` : 프로그램 순서, 두 자리 (01, 02, …).
- 전사 문단 ID `NN-MMM` : 세 자리 일련번호. 앵커 `segment-NN-MMM`. 링크 예: `[03-028](../<slug>-transcripts/03_서울대_이경무.md#segment-03-028)`.
- 슬라이드 번호 `슬라이드 NN` : 노트 안에서 매긴 번호. 사진 원번호가 다르면 `(원 사진 14)`처럼 병기.
- 파일명: 전사 `NN_<org>_<speaker>.md`, 노트 `NN_<org>_<speaker>.md` (같은 stem), 발표자·소속은 `event.yaml`의 값. 공백은 `_`.

## 1층 — 전사 `<slug>-transcripts/`

### `NN_<org>_<speaker>.md`

```
# <제목>

<발표자>, <소속> · <행사명> <날짜>

- Source audio: `<파일명>`  (복수면 줄 추가)
- Recorded: <YYYY-MM-DD> (<timezone>), started <HH:MM:SS> (event.yaml 기준)
- Duration: <HH:MM:SS>
- Language: <ko|en|mixed>
- ASR: <model>, <device>, <날짜> · 교정: <N>차 (<날짜>)

> Quality note: <저음량·잡음·누락 구간 등. 없으면 "특이사항 없음">

> 기계 전사 후 교정본이다. 고유명사·용어는 슬라이드·원문·공식 정보로 뒷받침될 때만 고쳤다. 불명확한 발화는 `[불명확]`로 두고 지어내지 않았다.

## [00:00:00] <장 제목 (내용 전환 단위, 교정 시 Claude가 붙임)>

<a id="segment-01-001"></a>
**[01-001] [00:00:00]** 문단 본문…

<a id="segment-01-002"></a>
**[01-002] [00:00:41]** 문단 본문… `[불명확: 들리는 대로 "…"]` …
```

- 문단화 규칙(`segment`): 세그먼트 간 침묵 ≥ 1.5초 또는 문단 길이 ≥ 45초 또는 ≥ 400자에서 끊는다. 한 문단은 시작 타임스탬프 하나를 가진다.
- `[불명확]` 표기: ASR 신뢰도 낮은 세그먼트(avg_logprob < -1.0 또는 no_speech_prob > 0.6)는 `[불명확: "<원문>"]`로 감싼다. 교정 시 Claude가 근거 있으면 풀고, 풀 때는 README 검증 기록에 개수를 적는다.
- 장 제목(`## [HH:MM:SS] …`)은 `segment` 초안에는 없고 교정 단계에서 붙인다. 없으면 lint가 경고.

### `README.md`

목록(날짜별 번호 목록, 링크) → `## 전사 처리 과정` (오디오 전처리, ASR 모델·장치, 교정 차수, 복수 녹음 교차 여부) → `## 검증 기록` (날짜, 무엇을 어떻게 확인했는지, 풀어 낸 `[불명확]` 개수).

### `unresolved-segments.md`

`| 문단 | 시각 | 들리는 대로 | 비고 |` 표. `lint`가 전사에서 `[불명확` 를 모아 재생성한다(사람이 쓴 비고 열은 보존).

## 2층 — 발표별 노트 `<slug>-notes/`

### `NN_<org>_<speaker>.md`

```
# <NN>. <발표자>, <소속> — *<제목>*

> 원자료: 전사 [NN_<…>.md](../<slug>-transcripts/NN_<…>.md) (문단 <K>개) · 사진 <P>장(슬라이드 <S>장) | 사진 없음(녹음만)
> 대조일: <YYYY-MM-DD>

## 요약

세 문장 이내. 발표가 주장한 것, 근거로 든 것, 남긴 질문.

## 1. <내용 절 제목>
## 2. …
```
- 내용 절은 발표 흐름 순. 각 문단의 주장 끝에 `([NN-MMM](../<slug>-transcripts/NN_….md#segment-NN-MMM))` 링크. 슬라이드로 확인되면 `(슬라이드 07)` 병기.
- 질의응답이 있으면 마지막 내용 절 `## N. 질의응답`.

```
## 슬라이드
```
- 사진이 있을 때만. `| 슬라이드 | 원 사진 | 시각 | 제목 | 핵심 내용 | 대응 문단 |` 표. 판독 불가 셀은 `(판독 불가)`.
- 사진이 없으면 이 절 대신 한 줄: `사진이 없어 녹음 전사가 원자료의 전부다.`

```
## 원문 대조 결과
### 확인
### 발언과 원문이 다른 것
### 검색했으나 찾지 못한 것
### 확인하지 않은 것
```
- 항목 형식: `- <대상>: <발언 내용>([NN-MMM]) → <원문 내용> ([링크]). 판정 근거.`
- 확인표(KDD식)가 유용하면 `### 확인표` 로 `| 문단 | 전사 표기 | 확인된 실체 | 링크 | 신뢰도 |`.

```
## 연구 라인에 걸리는 것
```
- 연구 라인 설정(`~/.config/lecture-recon/research_lines.yaml` 또는 config.yaml `research_lines:`, 예시 `configs/research_lines.example.yaml`)이 있을 때만 둔다. 없으면 이 절을 두지 않는다.
- 라인별로 소제목(`### <라인 이름>`). 근거 있는 연결만. 항목: `- <아이디어 이름>: <발표 근거([NN-MMM]/슬라이드)> → <우리 연구에서의 적용/비교점>`. 걸리는 게 없는 라인은 쓰지 않는다.

```
## 확인이 필요한 것
```
- 외부 인용 전에 원문을 봐야 하는 수치·고유명사·주장. 각 항목에 문단 ID 또는 슬라이드 번호.

### `README.md`

`# <행사명> 청강 재구성 노트` → 인용블록(재구성자, 원자료, 교정 차수) → `## 행사 정보`(일시·장소·주관·근거 링크) → `## 발표 목록`(번호, 링크, 발표자·소속, 제목, 사진 유무) → `## 자료 규모`(전사 문단 수, 사진·슬라이드 수) → `## 작업 기록`(날짜별).

## 3층 — 종합 리포트 `<slug>-report.md`

```
# <행사명> 종합 리포트

> 재구성: <사용자 이름> · 원자료: 현장 녹음과 사진(<N>차 교정본)
>
> 노트 컬렉션: [<행사명> 청강 재구성 노트](<slug>-notes/README.md).

## 한눈에 보기
- 행사: … (일시, 장소, 주관, 근거 링크)
- 발표 N건: 번호 목록 — [발표자, 소속](노트 링크): *제목*
- 자료: 전사 N건(문단 K개), 사진 P장(슬라이드 S장). 교정 차수.
- 이 리포트는 … 를 정리한다. (목적 한 줄)

## 자료 범위와 신뢰도
- 글머리 3~5개, 각 한 줄. 설명문·판정 분류 해설은 쓰지 않는다(노트에 있다).
- 원자료(녹음·사진 유무, 전사 모델, 교정 차수와 교정 수) / 불명확 개수와 푼 개수(목록 링크) / 원문 대조 날짜와 4분류 건수(노트 링크) / 발언과 원문이 다른 대표 사례 2~4건을 `발언 ↔ 원문값([NN-MMM])` 로 한 줄에

## 관통 주제
### 1. <주제>
도입 문단(어느 발표가 같은 흐름인지).
- [발표자](노트 절 링크): 주장([NN-MMM]) …
- 다르게 본 점: …
- 다루지 않은 발표: …
### 2. … (3~5개)

## 연구에 옮길 아이디어      (노트에 "연구 라인에 걸리는 것" 절이 있을 때만)
### <연구 라인 이름>
- <아이디어>([발표자](노트 절 링크)): 근거 → 적용.

## 확인이 필요한 것
- [발표자](노트 절 링크): …
- 공통: …
```
- "연구에 옮길 아이디어"는 노트의 "연구 라인에 걸리는 것"을 라인별로 모은다. 그 절이 있는 노트가 하나도 없으면 이 절을 두지 않는다.

## lint 규칙

1. 노트·리포트의 `#segment-NN-MMM` 링크가 전사에 존재.
2. 노트·리포트의 상대 링크 파일이 존재. 절 앵커(`#…`)는 GitHub 규칙(소문자·공백→`-`·구두점 제거)으로 헤딩과 대조.
3. `슬라이드 NN` 언급이 노트 슬라이드 표 범위 안.
4. 전사 `[불명확` 개수 = `unresolved-segments.md` 행 수.
5. 노트 필수 절 존재(요약 / 원문 대조 결과 / 확인이 필요한 것, 연구 라인 설정이 있으면 연구 라인에 걸리는 것도). config.yaml `required_sections:` 를 적으면 그 목록 그대로 쓴다. 사진 있는 발표는 `## 슬라이드` 필수.
6. 템플릿 placeholder(`<…>`, `TODO`)가 남아 있으면 경고.
